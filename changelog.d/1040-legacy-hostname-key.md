Added
- Importing, onboarding or adopting a machine whose configuration holds a legacy `machine.network.hostname` equal to the machine's name now removes that key alone from the stored base, so a later rename reaches the machine with its next release; the key stays where its value differs, the configuration already holds a `HostnameConfig` document, `machine.features.stableHostname` is set or a reference, or a mark covers it. A review mark on `stableHostname` or its mapping, made after such a removal, is refused with the rule `mark-on-released-hostname`: import again with that mark at the start. Refs ginsys/bronzeward#1040.
