# Test identity provider: the move from ZITADEL v4.19.5 to v4.20.6

28 November 2026. Outcome record for [ginsys/bronzeward#1274](https://github.com/ginsys/bronzeward/issues/1274).
It raises the pins of the disposable test provider and its login page, and repeats part of the
checks of [the first test-provider record](20261022-zitadel-test-idp.md) on the new pins. It selects
no identity provider for deployments, changes no authentication policy, inspects no deployment and
does not claim that any deployment is affected by the upstream advisories below.

## Why

Upstream advisory [GHSA-qqv8-37gw-ww2q](https://github.com/zitadel/zitadel/security/advisories/GHSA-qqv8-37gw-ww2q)
(published 18 November 2026): in Login V2, 4.0.0 to 4.20.4, a person who holds a user's first
factor can add an authenticator, a passkey for example, without the second factor that the user has
already enrolled. Force MFA does not close it. It is fixed in 4.20.5. Upstream backports nothing to
4.19. Eight more advisories of Login V2 and sessions, published on 13 November, are fixed in
4.20.3, and `v4.19.5` is inside the range of each (GHSA-3gwf-ph53-v73c, GHSA-vg5j-vf6h-586m,
GHSA-gx82-3gqq-j4h5, GHSA-3985-45jm-558m, GHSA-pm3x-9hh8-g745, GHSA-9vfg-mj6p-vwjc,
GHSA-fphg-99ff-7qrp and the host-header bypass GHSA-qvxq-53gh-64f6, whose range starts at 4.19.5).
The fixtures sign people in through the Login V2 page (participant sessions), so they should use a
patched release.

## The pins

`v4.20.6` (25 November 2026) is the newest 4.20 patch and holds the 4.20.5 fix. Compared with
4.20.5 it adds projection panic recovery, a registration-language fix in the login page and a
ListUsers query speed-up, and has no upgrade note. A new minor was not considered.

## Compatibility

`fixtures/dev-idp` needed no change: the start flags, the seeding calls, the groups target, the
login container's settings and the participant login policy all work at `v4.20.6` as they did at
`v4.19.5`. The upgrade notes of 4.20.0 and 4.20.3 were read for what could break the fixture (the
`session.link` permission, the public host header, password checks under the organization login
policy, the signed device-code check, Go 1.26 URL parsing). None did, as the runs below show.

## The authentication-method check

[`evidence/20261128-zitadel-pin/mfa-enrol-probe.mjs`](evidence/20261128-zitadel-pin/mfa-enrol-probe.mjs)
creates two synthetic humans, each with a TOTP second factor enrolled through the management API,
and drives the hosted Login V2 page in headless Chrome with a virtual passkey authenticator.

- **Attacker** (password only, no TOTP): open the passkey setup page by its address, the advisory's
  example, and press its button if the page offers one. The verdict is whether the user then has a
  passkey, read from the API.
- **Legitimate** (password, then the TOTP code): the same page and press, then the same read.

| Release | Attacker, first factor only | Legitimate, after the second factor |
| :--- | :--- | :--- |
| `v4.19.5` (control) | the page offers the passkey, and **a passkey is added** | passkey added |
| `v4.20.6` | the page refuses ("second factor required"), **no passkey added** | passkey added |

Outputs: [`probe-v4.19.5.txt`](evidence/20261128-zitadel-pin/probe-v4.19.5.txt) and
[`probe-v4.20.6.txt`](evidence/20261128-zitadel-pin/probe-v4.20.6.txt). The control matters: the
probe reproduces the flaw on the old release, so its refusal on the new one means something. The
`v4.19.5` run used a second checkout at `origin/main`, with the old pins, on loopback only. The
probe prints verdicts and page paths only; it keeps no password, code, token, screenshot or trace,
and removes its browser profile.

## Skips and limits

- **macOS.** The native archive and its checksum are not run here (no macOS host). CI's Safari job
  is the first run of `ZITADEL_DARWIN_ARM64_SHA256`; the archive's digest was checked by hand.
- **One setup page.** The probe tests the passkey setup page. Upstream's fix is one shared
  enrollment guard in front of the passkey, TOTP, OTP and security-key pages; the other pages were
  not driven. The refusal is read from the page's English text.
- **Not every advisory.** Only GHSA-qqv8-37gw-ww2q has a check. The 4.20.3 advisories are fixed by
  the release and were not each reproduced.
- **Not the full first record.** `go-idp` and `browser-auth` repeat the passing paths they covered
  before. The checks of the first record that were run by hand with `curl` (idle and absolute
  refresh-token expiry timing, the cross-origin token call, the groups claim with the target down)
  were not repeated by hand at `v4.20.6`.
- **The device page** of the participant sign-in is Zitadel's own built-in page, not Login V2; the
  web sign-in covers Login V2.
- One host, one release, plain http on loopback.
